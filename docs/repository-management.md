# 项目、版本与实验产物

一个仓库维护公共框架，各项目独立固定配置和结论。目录管理长期项目，短期分支管理代码或配置修改；不为每个模型维护长期分叉。

## 项目自包含

`projects/<名称>/configs/` 是独立配置根，内部保留 target、model、runtime、client、recipe、workload、campaign、logging 分类。引用不跨项目，也不使用隐式继承。

runtime/client 等小文件允许复制，确保一个项目升级镜像不会改变另一个项目。共享的是代码和规范，不是所有实验必须使用同一组参数。

从 [模板](../projects/_template/README.md) 创建项目。项目 README 写目标、验证状态、推荐入口和下一步；报告先结论后证据。模板源于真实配置，但新模型/硬件必须重新验证。

## 哪些内容进入 Git

| 内容 | 位置与处理 |
| --- | --- |
| 公共代码、测试、方法文档 | 正常提交；修复与项目结果分开描述 |
| 正式配置、当前有价值的候选 | 项目 configs；注明验证范围 |
| 精选报告、逐次小型汇总 | 项目 reports/data；正常提交，使用相对链接 |
| 完整日志、预热、原始 JSON、遥测 | 根 results；不进 Git，独立归档 |
| 草稿、自动生成的临时报告 | 根 reports；确认价值后再精选进项目 |
| 本地归档、临时工具、缓存 | 根 artifacts/tmp/cache；不进 Git |
| 权重、镜像、运行环境 | 外部管理；记录身份，不复制进源码包 |

不要全局忽略 `*.yaml`、`*.json` 或所有 `reports/`。本仓库只忽略根目录的运行产物，项目报告和数据仍可提交。源码包也不等于历史结果备份。

失败实验保留证据，但项目首页不堆全部尝试。把原因、绕过、停止条件及证据位置写成简短记录，避免后来重复踩坑。已提交配置的历史可通过 Git 追溯。

## 一次实验怎样冻结

运行前保存 commit、完整本地差异、镜像 ID/RepoDigest、解析配置、命令及模型身份。优先使用干净的冻结版本；若有本地修改，只报 commit 不足以复现。

运行期间不改代码或配置。新实验用新目录；不能把旧结果改写成新参数的结果。目录迁移也要保留旧身份和路径映射，不回写历史 JSON。

recipe 的说明文字也参与当前缓存指纹。仅改描述可能产生新缓存目录；复制/迁移配置时优先保持原字节和字段，既有缓存不删除，首次复现仍按 gate 预热。

## 多台机器如何合作

先固定公共 commit、镜像和基线 workload，再各自修改明确的 target 身份。各机器的 Codex 使用同一实验规范；公共阻塞由统一补丁解决，不各自修改 runner 或验收规则。

结果使用唯一 run 目录。汇总绝对性能及相对本机 baseline 的提升；最后同机复核优胜方案。baseline 校准阈值在实验计划中约定，不能事后按结果放宽。

当前执行器只做本机实验。后续 PD 可以增加角色部署、启动顺序和日志收集的编排层，继续复用现有测量与验收；控制节点和压测客户端的位置需要单独记录。

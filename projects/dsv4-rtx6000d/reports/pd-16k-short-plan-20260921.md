# 16K PD三小时原计划（执行前快照）

**目标：判断12卡TP4 2P1D在C64、C128下是否值得继续投入，并区分P供给、D处理、调度容量与传输等待。** 不以GPU利用率高低单独决定加P还是加D。优先寻找吞吐提高且延迟代价可接受的配置；若吞吐落后但关键延迟改善，单列取舍，不称全面胜出。尚未指定延迟上限，先报告实际代价。

#### 主测范围与时间预算

| 阶段 | 目标用时 | 内容／交付 |
| --- | ---: | --- |
| 准备 | 15分钟 | 核对空闲GPU、固定镜像与权重、KV容量、启动覆盖和实际CLI；新建工作区候选并validate/plan，冻结配置 |
| 启动与配对测量 | 140分钟 | 以下4个性能单元；普通和PD各一次部署，同一部署依次测C64、C128，每档独立预热 |
| 分析与归档 | 25分钟 | 普通／PD吞吐和延迟对照表、分阶段队列与运行批量、真实传输验收，以及下一步只走哪个分支 |

| 性能单元 | 数据／全系统并发 | 普通完整推理部署 | PD部署 | 双方总GPU |
| --- | --- | --- | --- | ---: |
| A：新批次C64对照，2组 | 16K／1K，C64 | 3个TP4服务 | 2个TP4 P＋1个TP4 D | 各12卡 |
| B：提高并发，2组 | 同一请求集，C128 | 同上 | 同上 | 各12卡 |

**每服务4卡，DSpark全部关闭。** 45控制并运行代理／客户端；拟复用46、47、48各后四卡，普通每节点1服务，PD为46/47各1P、48为1D；以执行前资源核查为准，配对双方使用相同GPU集合。服务沿用CPU32–47／NUMA2，45代理CPU16–19、客户端CPU20–23；NIC、UCX及侧通道端口沿用已通过的12卡配比组并核验。实际命令从plan或运行产物导出。

C64也重测，是为了让两档并发使用同批启动覆盖、配置与请求集。**两档每轮都取16K真实报告池前512条**，不拼接、不掺random；旧C64每轮256条的结果仅作历史参考，不合并统计。8K本轮复用已有对照给出适用范围，不新增8K矩阵；16K DSpark、TP2×DP2及新比例留待本轮证据决定。

#### 固定协议与验收

- 固定`vllm/vllm-openai:v0.29.0`及image ID `sha256:c2914767605584b6d8f45686b82de173ecc99e781897aa3d0a66dacd72c51ae1`、原NVFP4模型与FP8 KV；保留全部JIT缓存，接入[README的启动覆盖](../README.md)。P预算16384，D／普通8192，上下文32768；prefix cache与autotune关闭。两档保持相同服务配置。
- 首轮沿用每服务`max-num-seqs=64`及既有Graph尺寸，C128表示客户端在途上限。必须记录各服务运行数是否触及64：触顶且排队不能直接解释为GPU算力不足。容量或覆盖检查不通过时停止相应分支，不临场改参数并与旧轮混算。
- 每个性能单元为**1轮完整512请求HTTP预热＋固定3轮512请求quick**；temperature0、seed0、ignore_eos，输出固定1024。每完整轮应成功512、失败0，输入8,388,608、输出524,288 tokens。4个单元合计最多8192条性能请求，另最多32条功能请求；不追加预热或重试取好结果。
- 启动就绪上限900秒，每轮上限600秒，每个性能单元协议上限2400秒，均受剩余总预算约束。预热与正式分开保存，保留全部三轮及事件；报告吞吐均值、SD、CV，以及Mean／P95 TTFT、TPOT、E2EL。端到端计时经过同一代理并包含P及KV传输，不相加各服务独立速率。
- 同步记录P队列／处理时间、D队列／运行批量、代理各阶段在途数、NIXL计时与字节、CPU/GPU/NIC背景。联合核验P处理全输入、D远端命中与实际KV传输、无整段输入重算；传输失败、通知错误、过期及抢占均须为0。NIXL单rank计时不直接等同于请求关键路径。

#### 结果如何决定下一步

| 本轮证据 | 下一步仅选择一个方向 |
| --- | --- |
| PD有吞吐收益，延迟代价可接受，且无明显事件／漂移 | 保留对应并发候选，下一预算优先验证16K DSpark的兼容性与普通／PD配对 |
| P持续排队、D运行批量低，且无传输或容量异常 | 优先改善P供给；只提出一个P预算／拓扑／数量候选，按同GPU资源补普通参照 |
| D积压或运行数触及64 | 先区分调度上限、KV容量与计算压力，再选择容量验证或增加D；不直接认定需要2P2D |
| 两边批量不足，或传输／调度等待异常 | 先定位分流、流水线与通信开销，停止增加实例 |
| 两档均无吞吐或关键延迟优势，也无明确可修瓶颈 | 结束本轮TP4比例扩展；记录普通推理更合适，不为跑赢继续铺矩阵 |

**预算与停止条件：** 总目标180分钟，最后25分钟用于分析和清理；剩余时间不足以完成一组完整协议时不启动该组，未配齐或未满三轮标为PARTIAL。OOM、请求／工作量错误、KV验收失败立即停止相应部署并取证；正式JIT事件或吞吐CV>5%／明显漂移保留为quick问题结果，不补轮、不据此确认小幅收益。配置准备或启动超时优先压缩未启动单元，不自动增加部署重试；清理取证可略超时。

原始配置、逐轮结果、失败日志和命令快照拟保存于45本机`experiments/dsv4-pd-16k-short/`，运行时显式指定其`results/`下全新`--run-root`；精选报告与对照表再归档回本项目。该目录是待建立的执行工作区，本节是计划，不代表配置已验证或实验已开始。

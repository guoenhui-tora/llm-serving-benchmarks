# gpu-6000d-45：vLLM TP4 / SGLang TP4 对齐结果

**2026-09-17，gpu-6000d-45 的三对正式测量全部通过。** 在每实例 C32、输入 8192 / 输出 1024 tokens、128 请求下，vLLM 平均输出吞吐 **674.06 tok/s**，SGLang **583.47 tok/s**，vLLM 高 **15.53%**。两者吞吐 CV 分别为 **0.39% / 0.59%**，平均 TTFT 和 TPOT 也没有大幅波动。

结论仅适用于本节点 **GPU0–3 上 vLLM TP4、GPU4–7 上 SGLang TP4，同时开始压测**的配置。两服务始终加载；每轮 vLLM 先结束，SGLang 最后约 29–31 秒的测量发生在 vLLM 空闲期间。本轮没有交换 GPU 组，不代表独占部署、其他节点或两套同引擎副本的整机性能，也不能直接与历史 TP8 C32 比整机吞吐。

## 参数与 KV cache 对齐

模型和 tokenizer 均固定为 `/data/models/DeepSeek-V4-Flash-0731-NVFP4`。preflight 检查模型配置/tokenizer 哈希与所有权重分片大小一致，未对权重内容逐字节哈希。vLLM 0.29.0 镜像 ID 为 `sha256:c2914767605584b6d8f45686b82de173ecc99e781897aa3d0a66dacd72c51ae1`；SGLang 0.5.19-cu130 为 `sha256:d6e7288627be8b02be88e4bba38e73f6d50e2826869f753c13a4c4385ab3eda9`。客户端统一使用该 vLLM 镜像。

| 控制项 | vLLM | SGLang |
| --- | --- | --- |
| GPU / TP / PP / DP / EP | GPU0–3 / 4 / 1 / 1 / off | GPU4–7 / 4 / 1 / 1 / off |
| 上下文 / 活动容量 | 16384 / 32 | 16384 / 32 |
| KV dtype | `fp8_e4m3`，实际 `fp8_ds_mla` | `fp8_e4m3`，DSV4 FP8 非 RoPE + BF16 RoPE 布局 |
| 前缀复用 / FlashInfer autotune | 关闭 / 关闭 | 关闭 / 关闭 |
| Prefill 预算 | 8192，chunked prefill | 8192，mixed chunk；max prefill 8192 |
| Decode Graph | FULL_DECODE_ONLY | full；prefill disabled |
| Graph 捕获大小 | 1, 2, 4, 8, 12, 16, 24, 32 | 相同 |
| KV 控制 | `kv-cache-memory-bytes=34819194560` | `max-total-tokens=4440064`，`mem-fraction-static=0.90` |
| 页 / 滑窗策略 | block 256，FP4 indexer 关闭 | page 256，SWA/full ratio 0.1，FP4 indexer 未启用 |
| Sampling | seed 0、temperature 0、ignore_eos | 相同 |
| 投机解码 / CPU offload | 未启用 | 未启用 |

先用归档比例 vLLM 0.90 / SGLang 0.89 做了单次启动容量校准，两边功能和启动 gate 都通过。当时 vLLM 每卡权重约 39.84 GiB、可用 KV 预算 32.73 GiB；SGLang 权重约 40.94 GiB、池配置器的 KV 预算约 32.21 GiB。因此没有直接照搬 TP8 的约 51 GiB KV 配置。

正式 SGLang 固定实测子池：full=4,440,064、SWA=443,904、C4=1,110,016、C128=34,688，C4 state=27,744、C128 state=4,224。静态比例提高到 0.90 是为固定 token 上限留足预算，**实际子池规模没有增加**；正式启动日志和 required gate 均核验这些计数。

按固定镜像 `DeepSeekV4SingleKVPool`、`DeepSeekV4IndexerPool`、`CompressStatePool` 的张量布局，将上述实测规模换算为 **34,819,194,560 bytes = 32.4279 GiB/卡**，包括 KV、indexer、FP32 压缩状态和页填充。vLLM 显式使用同一字节预算；该参数生效时，recipe 保留的 `gpu-memory-utilization=0.90` 不再决定 KV 大小。

这是**根据实测池规模和实现计算的张量存储预算对齐**，不是分别用 profiler 直接测得完全相同的物理分配；不包括分配器碎片、映射表和其他引擎内存。各子池计算值随汇总 JSON 保存。两边逻辑 token 池计数不可直接相除。完整 C32 负载实际承载成功，日志未观察到 OOM、抢占或请求重算迹象。

客户端均使用固定 seed 的同一随机负载。SGLang 的 `/tokenize` 初始探测返回预期长度，没有触发 prompt 重写；vLLM 的该探测被客户端跳过。输入总量由客户端报告并严格校验，未逐请求另行保存服务端重新分词结果；输出总量按实际返回计数校验。

保留了 SGLang FP8 KV scale 默认 1.0、tokenizer/chat template 等 warning，以及两引擎 PCIe 四卡 custom all-reduce 不支持的回退。实际 attention/MoE 路径分别通过原有 gate 核验。同名 KV dtype 和短生成探测不能证明两引擎数值结果完全等价。

## JIT、预热和同步证据

预热与测量分目录保存，保留磁盘 JIT 缓存，整个正式运行不重启服务或修改配置/源码。每轮预热 C32、64 请求、完整 8192/1024 长度，最多 5 轮；至少连续两轮无已知编译事件，且相邻轮吞吐差不超过 5%。每对正式测量最多 2 次尝试；本轮三对都首次通过。

- vLLM 首次预热共 5 轮：吞吐 438.56、675.93、510.72、679.29、673.12 tok/s；事件数 36、0、24、0、0。第三轮确实再次出现 TileLang 编译，计数按规则重置，最后两轮相差 0.91%。
- SGLang 首次预热共 3 轮：457.55、585.61、588.69 tok/s；已知编译事件均为 0，但前两轮变化 28%，因此继续预热，最后两轮相差 0.53%。首轮性能变化的具体根因未完全定位，不能把无日志匹配解释成没有任何 JIT 活动。
- R2/R3 前两边各用 2 轮预热通过，安静轮吞吐差分别为 vLLM 0.13%/0.06%、SGLang 0.17%/0.16%。全程共 16 轮外部预热、1,024 个预热请求；这些都不计入正式 768 请求。
- 六个正式测量窗口均无已知编译事件，完整服务日志 kernel gate 为 PASS。启动/预热事件与 warning 全部保留，不以删除 warning 或放宽识别规则取得 PASS。

固定客户端仅在官方 benchmark 计时器前插入屏障，并记录计时起止时间；请求生成、传输和指标算法沿用固定镜像实现。屏障位于客户端初始单请求探测之后。初始探测不计入 128 请求窗口，但其日志编译事件同样会拒绝该次尝试。

| 重复 | 计时起点偏差 ms | 双方重叠 s | SGLang 尾段 s |
| --- | ---: | ---: | ---: |
| R1 | 5.02 | 193.64 | 30.83 |
| R2 | 1.35 | 195.14 | 30.92 |
| R3 | 5.73 | 194.58 | 28.83 |

没有另发填充请求来延长较快一侧的负载，所以不能把较慢一侧的完整测量窗口称为全程双负载稳态，也不能从汇总指标恢复仅重叠窗口的吞吐。

## 资源条件与复现

容器 inspect 验证了 CPU/内存节点限制：vLLM 服务 `0-13,64-77`、客户端 `14-15,78-79`、内存节点 0；SGLang 服务 `32-45,96-109`、客户端 `46-47,110-111`、内存节点 2。各为 14 物理核服务 + 2 物理核客户端，位于各自 GPU 近端 NUMA。未逐页验证实际内存驻留位置。

正式窗口每 5 秒采样：vLLM 显存 78,653–78,717 MiB/卡、温度 42–57℃、SM 频率 2257–2422 MHz；SGLang 显存 79,811 MiB/卡、温度 52–59℃、SM 频率 2415–2422 MHz。vLLM 窗口早期存在短暂较低频率，三次完整窗口结果仍稳定。GPU 采样中只见本次八个计算进程；功耗上限保持 600 W/卡，未锁频或修改宿主设置。低频采样不能排除更短干扰。

以下从仓库根目录执行。本项目的 [paired_run.py](../scripts/paired_run.py) 是 **45 节点固定资源/C32/三重复协议的复现脚本**，复用公共模块，不是公共 runner 的通用同步功能；客户端插桩见 [paired_client.py](../scripts/paired_client.py)。两份 campaign 单独使用 `bench run` 不会复现双服务同步条件。

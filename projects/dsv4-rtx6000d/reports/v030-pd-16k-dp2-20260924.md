# vLLM 0.30，3P1D：16K：P/D 均 TP2 DP2

**16K/1024、C128/D128 的 v0.30 TP2 DP2 3P1D quick 已完成：3091.86±18.69 output tok/s，Mean TTFT 10.254±0.233 s，Mean TPOT 28.391±0.271 ms。** 1536条正式请求全部成功，三轮均0已知JIT，D每轮命中全部8,388,608输入tokens且整段prefill重算为0。本次DP2在只加载MXFP4草稿修复、保留缓存和原生启动准备下跑通，不再需要旧DP profiling回移或定向预热worker。

相对历史同放置v0.29 C128/D128的3067.25±9.80 tok/s、TTFT11.722s、TPOT27.371ms，本次吞吐+0.80%、TTFT−12.52%、TPOT+3.73%。这是版本/预算/预热策略不同的历史方向对比：本次P budget16640，旧组16384；不能据此单独归因于v0.30，也不能回答PP2是否更优。吞吐CV0.60%；TTFT和TPOT仍有波动，不把quick改称stable。

正式合并草稿接受率约47.7%。三轮每轮NIXL成功传输1024次、88.261 GB；各P及两个D引擎均实际参与，零传输/通知失败、零KV过期、零抢占。固定TTFT≤10s且TPOT≤50ms时，goodput为2.361±0.059 req/s，联合达标率78.19%，仍未达到95%目标。

P端各服务平均排队约3.45–4.08s、prefill约4.50–4.78s；D排队约0.27–0.28s，其prefill阶段统计含远端KV处理，不能解释为D重算输入。P仍是TTFT的重要组成，不能仅看D的decode速度。低频资源采样显示各服务GPU平均利用率约61.5%–69.4%，最高温度64°C；服务CPU集合平均忙碌约50%–65%。这些是阶段窗口统计，包含客户端准备及首尾，不能排除瞬时干扰或把GPU未满负载直接判为单一通信瓶颈。

保留SymmMem/FlashInfer All Reduce在SM120上不可用的warning。首次尝试四服务已READY，但客户端功能数据元数据不符，在发HTTP前退出；修复仅建立独立短输出功能数据副本，第二次完成，未按性能挑选启动。随后24K DP2已自动接续；本次owned容器清理成功，冻结文件没有改变。

所有P固定每引擎max-num-seqs=32，因此PP2的每P服务合计容量32，DP2的每P服务合计容量64；P的budget也按引擎配置。物理GPU相同不等于逻辑调度容量相同，本批比较既定recipe组合，未做同服务总容量的纯拓扑消融。

另外，实际NIC配置也有差异：NIXL各服务沿用`UCX_NET_DEVICES=mlx5_4:1,mlx5_5:1,mlx5_6:1,mlx5_7:1`，包括46前四卡的P2；Mooncake显式使用单个NIC，P2为`mlx5_0`、其余为`mlx5_4`。没有做同connector/同NIC的控制实验，不能从本批分离这些因素的贡献。

## 协议与固定条件

3P1D 共16张 RTX6000D。P0＝46后四卡、P1＝47后四卡、P2＝46前四卡；D＝48后四卡。P0/P1/D绑定CPU32–47/NUMA2，P2绑定CPU0–15/NUMA0；45只运行代理CPU16–19与客户端CPU20–23。实际NIC、端口及所有参数以本篇实测命令为准。

服务固定 `vllm/vllm-openai:v0.30.0`，image ID `sha256:8a69ffad015f138d7170c4ddc429e230a3bc1c1719f67e14324749df200a4b90`；客户端沿用 v0.29 image ID `sha256:c2914767605584b6d8f45686b82de173ecc99e781897aa3d0a66dacd72c51ae1`。权重 `/data/models/DeepSeek-V4-Flash-0731-NVFP4` 只读，各节点核对config/index/tokenizer身份，未声称全量权重重哈希。

全组 EP on、DSpark K5、greedy draft、standard rejection、adaptive verification off、MRV2、async scheduling。只用固定 MXFP4 草稿分派修复及加载对象核验；没有旧DP回移、mHC自定义worker或定向kernel预热。Mooncake候选另外带源文件哈希固定的传输观测代码，须与原始NIXL配置区别。保留磁盘JIT缓存，由同版本已有缓存复制到每个recipe独立目录，不是冷缓存启动。

每个并发先1轮2C完整请求warmup，再3轮各4C正式。temperature0、seed0、request_rate=inf、ignore_eos；固定数据前N条，prefix cache off、FlashInfer autotune off。每次部署最多8条完整输入/16输出的独立功能探测，不计正式结果。未因JIT、CV或低吞吐追加轮次。

沿用历史 `govreport-16k-prefix-1024-v2.jsonl`，SHA256 `025246b18d8ba7e1bc4d98c1a20b32b570860bb06a0baf0cea4ae97403d982e7`；实际tokenizer核对前512条均为16384输入，固定1024输出。C128/D128，warmup256条，正式每轮512条。P budget16640，D budget16384；历史v0.29 P budget为16384，因此版本历史比较还含预算与预热策略差异。

P每引擎容量32，target/draft Graph覆盖192/160。D128的PP2覆盖768/640，DP2每引擎容量64、覆盖384/320。GPU显存比例0.9，max-model-len32768，FP8 E4M3配置/DSV4 packed MLA，block256。

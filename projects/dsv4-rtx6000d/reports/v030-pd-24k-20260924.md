该24K数据池与16K历史前缀池身份不同，且输出长度、D容量及P budget同时变化，不能把跨负载吞吐差异单独归因为输入长度。PP2与DP2同为P每引擎容量32，意味着每P服务合计容量分别32与64；D服务总容量固定80。

首个DP2尝试已完成C32，但切换C48时脚本缺少该workload ID的数据路径映射，在发请求前报KeyError并清理。修复后完整重跑四档，保留JIT缓存；首次C32只作失败部署的诊断记录，不拼接或挑选更快结果。修复通过8个离线workload命令检查，没有修改模型源码、负载长度或性能gate。

完整DP2重跑的C32/48/64/80吞吐分别1607.41±14.60、2056.50±21.66、2430.03±12.10、2759.73±5.28 tok/s；Mean TTFT分别5.167、6.315、7.436、9.107s。DP2相对PP2吞吐分别+25.44%、+25.70%、+25.66%、+28.27%；Mean TTFT分别−8.75%、−8.54%、−7.86%、−3.04%。C80是本矩阵最高吞吐档，C64则有更低TTFT；没有扩大到更高并发。

按TTFT≤10s且TPOT≤50ms的联合SLO，PP2从C32的82.03%降至C80的77.29%，DP2从86.72%降至78.13%。对应goodput，PP2为0.513/0.635/0.741/0.812 req/s，DP2为0.681/0.832/0.959/1.053 req/s。均未达到95%联合目标；不能只按平均TTFT选线上配置。

两拓扑均命中全部远端输入KV、D整段prefill重算为0、传输/通知失败/过期/抢占均0。PP2按逐请求的四个TP/PP producer rank完成记录验收，DP2按NIXL两TP rank传输及两个DP引擎验收；三条API P→D路径均覆盖。所有正式及warmup窗口均无已知JIT。短功能与计数检查不替代完整质量评测。

资源采样中D的KV峰值不超过约22%；PP2没有capacity waiting，DP2仅C80短暂观察到1条capacity waiting，不支持将结果差异归为KV耗尽。D排队均值范围PP2约0.60–1.25s，DP2约0.20–0.26s，connector及调度等待也影响端到端结果。PP2组最高GPU温度64°C，DP2为61°C；保留SM120相关warning，低频采样不能排除瞬时CPU/通信干扰。未改变宿主功耗或锁频。

## 协议与固定条件

3P1D 共16张 RTX6000D。P0＝46后四卡、P1＝47后四卡、P2＝46前四卡；D＝48后四卡。P0/P1/D绑定CPU32–47/NUMA2，P2绑定CPU0–15/NUMA0；45只运行代理CPU16–19与客户端CPU20–23。实际NIC、端口及所有参数以本篇实测命令为准。

服务固定 `vllm/vllm-openai:v0.30.0`，image ID `sha256:8a69ffad015f138d7170c4ddc429e230a3bc1c1719f67e14324749df200a4b90`；客户端沿用 v0.29 image ID `sha256:c2914767605584b6d8f45686b82de173ecc99e781897aa3d0a66dacd72c51ae1`。权重 `/data/models/DeepSeek-V4-Flash-0731-NVFP4` 只读，各节点核对config/index/tokenizer身份，未声称全量权重重哈希。

全组 EP on、DSpark K5、greedy draft、standard rejection、adaptive verification off、MRV2、async scheduling。只用固定 MXFP4 草稿分派修复及加载对象核验；没有旧DP回移、mHC自定义worker或定向kernel预热。Mooncake候选另外带源文件哈希固定的传输观测代码，须与原始NIXL配置区别。保留磁盘JIT缓存，由同版本已有缓存复制到每个recipe独立目录，不是冷缓存启动。

每个并发先1轮2C完整请求warmup，再3轮各4C正式。temperature0、seed0、request_rate=inf、ignore_eos；固定数据前N条，prefix cache off、FlashInfer autotune off。每次部署最多8条完整输入/16输出的独立功能探测，不计正式结果。未因JIT、CV或低吞吐追加轮次。

数据为用户提供的 `govreport-isl24576-exact-n512.jsonl`，SHA256 `615edb29e5a171e8f4dc7679739437202cddf8d93887f7b9a7260bc9e6d68170`。实际tokenizer核对所需前320条均为24576输入，固定2048输出。P budget24832，D budget16384；D服务容量80。并发32/48/64/80，warmup为64/96/128/160条，正式每轮128/192/256/320条。

P每引擎容量32，target/draft Graph覆盖192/160。D80的PP2覆盖480/400，DP2每引擎容量40、覆盖240/200。GPU显存比例0.9，max-model-len32768，FP8 E4M3配置/DSV4 packed MLA，block256。
